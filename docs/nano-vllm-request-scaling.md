# Qwen3-8B: масштабирование числа запросов и абляция prefix cache

Пилот: 3 независимых workload seed (42, 43, 44) × 5 размеров пакета (1, 2, 4, 8, 16) × 2 состояния межзапросного prefix cache, всего **30 запусков и 186 измеряемых запросов**. Во всех запусках используется `upstream_dynamic`; режим `fixed_batch` не включён. Условия внутри каждого повтора перемешиваются отдельно с `dataset.order_seed` и записываются в `plan.json`.

Каждый повтор задаёт перестановку 16 длин от 3000 до 13000 токенов и воспроизводимые входные token IDs. Пакеты меньшего размера — начальные сегменты этой перестановки; условия cache ON/OFF используют в точности одинаковые входы и sampling. Каждому запросу задано 1000 выходных токенов и `ignore_eos=true`. Проверяйте фактические окончания и размеры выходов. Малые пакеты покрывают только часть длин; три повтора не обеспечивают равномерного покрытия диапазона.

Cache ON прогревается отдельным донором на запрос: 1024 общих токена и один отличающийся хвостовой токен. Доноры вне таймера, до 93 для всей серии; удержание блоков до размещения соответствующего запроса — дополнительное вмешательство. OFF не выполняет донорские вызовы и отключает межзапросный prefix reuse, но сохраняет KV-cache для decode. Фактическое повторное использование и возможные ошибки следует смотреть в событиях, а не приравнивать к запланированным 1024 токенам. Замер ON не включает стоимость подготовки кэша и не является полной оценкой end-to-end ускорения. Кроме доноров, адаптер выполняет один warmup-запрос на каждый запуск; внутренний warmup модели считается отдельно.

Настройки по умолчанию: Qwen3-8B, TP=2, BF16, eager, 32768 max context, 16384 max batched tokens, 8 max sequences, блок KV 256. Последний лимит последовательностей в этом upstream dynamic scheduler относится к выбранным за шаг последовательностям и не является строгой границей всего running set. Установки и доступная KV-память должны быть одинаковыми/зафиксированными и достаточно большими для нагрузки; реальная выполнимость зависит от GPU.

Из корня репозитория, CPU-only план без скачивания модели:

```bash
uv run --locked python experiments/nano_vllm_qwen3_8b_long_context/run.py --config-name request_scaling mode=plan
```

На совместимом GPU-хосте, после установки inference extra и подготовки модели, можно проверить один запуск `mode=run dataset.run_limit=1`, а затем отдельным запуском выполнить всю матрицу с `mode=run`. Выбор GPU задаётся пользователем через окружение. Проверка `mode=preflight` в этом entrypoint отключена и не подтверждает готовность. Настройка `mode=overhead` унаследована от другого workload и не является согласованной калибровкой этого пилота. Структурная валидация/приёмка в текущем сборщике отключены; наличие артефактов не означает их принятия. Измеряется офлайн вызов `generate`, а не клиентский serving/SLO. Реальный GPU запуск необходим для подтверждения работоспособности и измерения cache reuse.
